Gridzilla: a grid signaling platform for grid-serving storage

A DSO-controlled platform that sends signed charge and discharge signals to home batteries in a congested grid segment, reaching Victron, GoodWe and any other system through three vendor-agnostic paths, with the owner's limits and a fail-safe enforced at the device.

1. The big picture

The DSO never talks to an inverter directly. It publishes a signal for a grid segment. The signal travels over one of three paths and ends in a local policy agent next to the battery. That agent is the only thing that writes to the inverter, and it always merges the signal with the owner's own limits.

Gridzilla is the DSO's monster. It stomps on congestion, but every house keeps it on a leash.

Why the platform is the main point. Vendor clouds, local agents and standards gateways all change over time. The platform's job is to own the one thing that must stay stable: a signed, bounded, segment-scoped signal with a clear meaning. Vendors integrate with that signal once, on whichever path suits them.

2. The signal

A signal is an envelope at the grid connection point, never a device setpoint. The DSO says how much the home may import or export and for how long. The home decides how to achieve it with whatever hardware it has.

ABSORB PV surplus congestion

Midday, feeder voltage rising. Signal: lower the export limit and allow grid charging. The battery soaks up local PV instead of pushing it onto the feeder.

SUPPORT load peak congestion

Evening, heat pumps and chargers on. Signal: lower the import limit. The battery covers the house load, so the transformer sees less demand.

RELEASE event over

Explicit end of the event. Also implied when the window expires or the heartbeat stops. Owner mode resumes.

3. Inside the local policy agent

This is where cybersecurity and owner protection live, and it is the same logic on all three paths. For the demo it is a Node-RED flow on a Cerbo GX. In a vendor cloud it would be the same rules in firmware.

4. Worked example: a Victron plant on VRM

One of the plants on VRM is the reference installation. Cerbo GX, MultiPlus-II, MPPT chargers, a battery with BMS, and a grid meter at the connection point. The local policy agent is a Node-RED flow on Venus OS. This is also the live demo for the interim pitch.

5. Threats and controls

The threat model starts from how these systems are deployed today: Modbus TCP without authentication on home networks, port forwarding to reach the GX remotely, and vendor clouds that can push settings to whole fleets.

ThreatControlWhere
T1 Spoofed or tampered signalPlatform signs every signal; agent verifies against a pinned platform keyPlatform, agent

T4 Compromised vendor cloud (Path A)Cloud relays signals but cannot forge them; the agent still verifies the platform signature end to endAgent

7. What goes into the IES profile, and what stays in the pitch

  • Profile (the deliverable): actors, the three signal modes, the transactions (register, publish signal, acknowledge, heartbeat, release, report), the security requirements per transaction, and the owner-protection rules. No protocols, no registers.
  • Pitch (evidence): the Victron mapping, the GoodWe mapping and the live demo, to show the profile is implementable on hardware sold today.
  • Open questions for the mentors: who runs the segment registry, how registration is tied to the meter point, and whether Path C must be mandatory for compensation.
